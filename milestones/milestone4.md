## Reflection

### 1. What went well during this unit?

This unit went well because we made visible progress on the core recipe management flow with cooking plan and the recipe import backend implemented. The app now has a more user-friendly home page, users can browse saved recipes, search and filter recipes, and manually create recipes with ingredients. We also added support for optional recipe images and servings, which makes the recipe cards more useful and polished.

### 2. What were some challenges your group faced in this unit?

One challenge was keeping the scope clear when making issues. We separated the frontend and backend to different issues such that it will be easier to pursue without 1 issue had to be dependent on others

### Did you finish all of your tasks in your sprint plan for this week? If you did not finish all of the planned tasks, how would you prioritize the remaining tasks on your list?

We completed the scoped recipe management backend and frontend, cooking plan and recipe import backend tasks for this unit: browsing recipes, creating recipes, connecting to the backend API, handling loading/empty/error states, and adding search/filter functionality. Remaining work should be prioritized by finishing full frontend flows for features that already have backend support, especially recipe import from URL and cooking plans.

### Which features and user stories would you consider “at risk”? How will you change your plan if those items remain “at risk”?

Grocery list generation, user favorites are the main features at risk because they require frontend flows and backend implementation. If they remain at risk, we will reduce scope by focusing first on the user flows that connect directly to our core app goal: saving recipes, planning meals, and generating grocery lists.
